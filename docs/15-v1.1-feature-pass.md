## 2. Phase 1 — Divider redesign

### The problem, restated precisely

The original five variants differed only in **colour and spacing**:

| | Fill | Width | Thickness | Glyph | Motion |
|---|---|---|---|---|---|
| Standard | flat | 100% | 1px | no | none |
| Minimal | flat | 100% | 1px | no | none |
| Gradient | gradient | 100% | 1px | no | none |
| Decorative | gradient | 100% | 1px | yes | none |
| Animated | gradient | 100% | 1px | yes | hover |

Gradient / Decorative / Animated shared one shape; Standard / Minimal were
identical but for margin. Set the colours the same and four of the five
became indistinguishable.

### Root cause

The `hr` was drawn as `border-bottom` on a **zero-height element**. A border
offers exactly one expressive axis (colour), so variants had nowhere else to
differ.

### The fix

`hr` is now a **real box with a background**, which unlocks five independent
geometric axes:

```
--primidian-divider-width          the rule need not span the full measure
--primidian-divider-thickness      real height, not border-width
--primidian-divider-image          gradient fill instead of flat colour
--primidian-divider-cap-*          dots at each end
--primidian-divider-shimmer-*      a travelling highlight layer
```

### Result — verified distinctness matrix

```
Style        Thick  Width  Caps   Glyph          Shimmer
──────────────────────────────────────────────────────────
Standard     2px    100%   block  none           none
Minimal      1px     38%   none   none           none
Gradient     2px    100%   none   none           none
Decorative   1px     92%   none   inline-block   none
Animated     2px    100%   none   none           block
```

All five signatures are unique, and every pair differs on **at least two**
axes. The build audit asserts this mechanically, so a future edit that
collapses two variants back together will fail the check.

Because the differences are geometric, the styles stay distinguishable when
every colour token is set identically — the explicit requirement.

### Animated: genuinely animated

Not the static gradient with a hover effect. A narrow highlight travels the
rule on a slow loop:

- The shimmer layer spans the full rule and carries a **narrow gradient as
  its background**; the layer is translated `-100% → +100%` of itself.
  Percentages resolve against the element, so the sweep is correct at any
  rule width with no `vw` units or brittle arithmetic.
- `transform: translate3d` only — compositor, no repaint, no layout.
- The base rule sits at `opacity: 0.55` so the highlight has contrast to
  read against; with animation off it returns to `1` so the divider never
  looks half-finished.
- Suppressed entirely (not merely shortened to `0.01ms`, which would leave
  it frozen mid-track) under `prefers-reduced-motion` and under the global
  animation toggle.

### Bonus axis

A `Line Pattern` `class-select` (Solid / Dashed / Dotted) composes with any
of the five. Implemented as a `mask-image` rather than `border-style` so it
works with gradient fills and fractional thicknesses.

## 4. Phase 3 — Tab animations (clean-room)

### What was studied in Primary

Selectors examined: `.workspace-tab-header`, `.is-active`, `:not(.is-active)`,
`:hover`, `:active`, `-inner`, `-inner-icon`, `-inner-title`,
`-inner-close-button`, `-status-icon`, `-container`, `-container-inner`,
`-new-tab`, `-tab-list`, plus `.mod-root` / `.mod-left-split` /
`.mod-right-split` / `.mod-stacked` scopes.

Five behaviours produce Primary's tab feel:

| # | Behaviour | Primary's mechanism |
|---|---|---|
| 1 | Inactive hover | `transform: translateY(-2px)` — a lift |
| 2 | Inactive press | `transform: translateY(+2px)` — a sink |
| 3 | Active tab | layered inset `box-shadow`: light top line, dark bottom line, small drop shadow — a raised card |
| 4 | Active emphasis | border, icon and title take one colour simultaneously |
| 5 | Close button | fills with that colour on hover, glyph flips to on-accent |

Primary keyframes: **none** for tabs — the feel is entirely transitions.
Confirms the transition-first philosophy already recorded in `docs/02` §3.

### What Primidian implements, and how it differs

| Aspect | Primidian |
|---|---|
| Hover lift / press sink | Same *vocabulary*, own tokens (`--primidian-tab-lift`, `--primidian-tab-press`), own values |
| Active raised card | Own inset shadow built from `color-mix()` on Primidian tokens |
| Accent scheme | **Single accent.** Primary rotates 3 colours via `:nth-child(3n+1/2/3)` — that is Primary's Bauhaus identity and would clash with Obsidianite's two-accent scheme |
| Indicator | **Primidian addition.** `scaleX` wipe from centre; Primary has no equivalent |
| Transition syntax | Explicit `property duration easing` triplets. Primary's `transition: border, box-shadow, transform var(--button-anim)` is a **malformed comma list** where only the last segment gets a timing function — a genuine bug, not replicated |
| Close button | Own scale-in reveal + accent fill |

**No Primary CSS text was copied.** The behaviours above are interaction
design patterns (hover-lift, press-sink, elevation-via-inset-shadow), which
are ideas rather than protected expression. Values, tokens, selectors and
keyframes are independently authored.

### Constraints honoured

- Only `transform`, `opacity`, `color`, `background-color`, `box-shadow`
- No `width` / `height` / `margin` / `padding` transitions — asserted by audit
- `body:not(.primidian-animations-off)` gates both keyframe animations
- `prefers-reduced-motion` handled globally by `81-motion.css`
- New granular opt-out: **Disable Tab Motion** keeps colour feedback
- Mobile keeps the close button visible (no hover state on touch)

## 5. Phase 4 — Glow system (Reworked)

### The scaling problem

A naive implementation needs one glow rule per component per colour. With
~20 glow-capable elements that is unmaintainable, and it cannot satisfy
requirement 5 (glow follows the element's *own* configured colour).

### The solution: two resolved tokens + `color-mix()`

```css
--primidian-glow-alpha: clamp(0%, calc(base × intensity × opacity × 100%), 95%);
--primidian-glow-blur:  clamp(0px, calc(base × intensity), 48px);
```

Each component then needs **one declaration**, passing its own colour token:

```css
box-shadow: 0 0 var(--primidian-glow-blur) var(--primidian-glow-spread)
            color-mix(in srgb, <OWN-COLOUR> var(--primidian-glow-alpha), transparent);
```

Because the component supplies its own colour, recolouring a divider
recolours its glow automatically — no per-component glow settings, no extra
CSS. Requirement 5 satisfied structurally.

### Per-element toggles

Each glow target has an independent class-toggle setting:

| Toggle | CSS Class | Default |
|---|---|---|
| Text | `primidian-glow-text` | Off |
| Headings | `primidian-glow-headings` | On |
| Links | `primidian-glow-links` | On |
| Tags | `primidian-glow-tags` | On |
| Highlights | `primidian-glow-highlights` | On |
| Dividers | `primidian-glow-dividers` | On |
| Tables | `primidian-glow-tables` | Off |
| Buttons | `primidian-glow-buttons` | On |
| Checkboxes | `primidian-glow-checkboxes` | On |
| Toggles | `primidian-glow-toggles` | On |
| Sliders | `primidian-glow-sliders` | On |
| Inputs | `primidian-glow-inputs` | On |
| Tabs | `primidian-glow-tabs` | On |
| Sidebar | `primidian-glow-sidebar` | On |
| Borders | `primidian-glow-borders` | Off |
| Code | `primidian-glow-code` | Off |

### Text glow vs UI glow

- **Text glow** uses `text-shadow` — clean glow without backgrounds, outlines, or blurry glyphs.
- **UI glow** uses `box-shadow` — appropriate for borders, controls, and surfaces.

### Global controls

- **Enable/Disable** — master switch (off by default)
- **Intensity** — scales blur and opacity (0–2, default 1)
- **Blur Radius** — base radius at intensity 1 (in pixels)
- **Opacity** — base opacity at intensity 1 (0–1, default 0.45)
- **Global Opacity** — multiplier for all glow effects (0–1, default 1)
- **Spread** — extra spread beyond blur (in pixels)
- **Corner Radius** — glow corner radius (in pixels)
- **Pulse Animation** — optional pulsing effect (off by default)
- **Pulse Duration** — pulse cycle duration (in seconds)

### Numeric settings

All numeric glow settings use predefined CSS units. Enter only the number:

| Setting | Unit | Example |
|---|---|---|
| Blur Radius | px | `8` (becomes `8px`) |
| Spread | px | `0` (becomes `0px`) |
| Corner Radius | px | `0` (becomes `0px`) |
| Pulse Duration | s | `3` (becomes `3s`) |

### The off-switch

`body.primidian-glow-off` sets `--primidian-glow-alpha: 0%` and
`--primidian-glow-blur: 0px`. Every glow resolves to a fully transparent,
zero-radius shadow — nothing is painted, and **no component needs its own
"glow off" rule**. Turning glow off is one token change, not N removals.

### Applied selectively (requirement 4)

Headings · link hover · dividers + glyph · checkboxes (checked, per
task-state colour) · tags (hover) · active tab indicator · focused inputs ·
CTA hover · line numbers · highlights · blockquote edge · buttons · toggles ·
sliders · tabs · sidebar items.

**Not** applied to body text or large surfaces.

### Why `box-shadow`/`text-shadow`, not `filter: drop-shadow`

`filter` creates a containing block for absolutely-positioned descendants and
forces a new stacking context, which would break the divider glyph and
heading accent bar. Verified absent by audit.

Suppressed entirely under `forced-colors`.

### Accessibility

- Glow is suppressed entirely in Windows High Contrast mode (`forced-colors: active`).
- Pulse animation respects `prefers-reduced-motion`.
- Glow reduces effective contrast at high intensities — use with care.

## 6. Phase 5 — Colour picker: two causes, one ours

### Cause A — ours, fixed

I extracted Pickr's real parser from the plugin bundle:

```js
hsla: /^((hsla)|hsl)[\D]+([\d.]+)[\D]+([\d.]+)[\D]+([\d.]+)[\D]*?([\d.]+|$)/i
```

and ran all colour defaults through it. **14 defaults parsed with alpha < 1**,
because `opacity: true` had been set on **all 73** themed-colour settings —
including accent, backgrounds, text and headings, which should never be
translucent. For those, the checkerboard was Pickr **correctly** signalling
transparency.

Fixed: `opacity: true` removed from **65** settings; retained on the **8**
whose defaults are genuinely `hsla()`:

```
primidian-border · primidian-highlight-bg · primidian-link-internal-accent
primidian-link-external-accent · primidian-inline-code-bg · primidian-quote-bg
primidian-tag-bg · primidian-table-border-color
```

Audit now asserts: 0 opaque settings allow transparency, 0 translucent
settings are blocked from alpha, and every non-opacity default parses as
alpha = 1 under Pickr's actual regex.

### Cause B — upstream, documented not masked

Style Settings v1.0.9, `ThemedColorSettingComponent`:

```js
this.createColorPickerLight(S, this.containerEl, p, c || "", i);
//                                                  ^^^^^^ undefined → ""
createColorPickerLight(t, a, i, l, c) {
    let p = l !== void 0 ? l : this.setting['default-light'];
    //      "" !== undefined  → p = ""     ← the default is never reached
    f.style.setProperty('--pcr-color', p);
    //  CSSOM: setProperty(name, "") REMOVES the property
}
```

`--pcr-color` is therefore unset, `.pcr-button::after { background: var(--pcr-color) }`
paints nothing, and the `::before` checkerboard shows through.

Scope: **every `variable-themed-color` that the user has not yet saved a value
for.** Once saved, `c` is a real string and the swatch renders. Notably
`variable-color` (non-themed) does **not** have this bug — it uses
`i !== void 0 ? i : this.setting.default` correctly.

**Not worked around.** Per instruction, no CSS hides the checkerboard —
verified by audit (`no CSS hack hiding the checkerboard`). Cause A was the
part under our control and it is fixed; Cause B needs an upstream patch.

## 7. Phase 6 — Line numbers: DOM investigated first

### Live Preview (CodeMirror 6) — supported ✅

Each source line is its own element:

```html
<div class="cm-line HyperMD-codeblock HyperMD-codeblock-bg">…</div>
```

with `.HyperMD-codeblock-begin` / `-end` marking the fences. Discrete sibling
elements → CSS counters are reliable.

```css
.HyperMD-codeblock-begin { counter-reset: primidian-codeline; }
.HyperMD-codeblock:not(-begin):not(-end) { counter-increment: primidian-codeline; }
.HyperMD-codeblock:not(-begin):not(-end)::before { content: counter(primidian-codeline); }
```

### Reading Mode (Prism) — structurally impossible ❌

Obsidian emits **one text node** containing newline characters:

```html
<pre><code class="language-js">line1\nline2\nline3</code></pre>
```

There is no per-line element. CSS counters increment per **element**, and no
selector can address a line of text inside a text node. This is a structural
limit of the DOM, not a difficulty to be engineered around.

**Corroborating evidence:** Obsidianite shipped ~40 lines of Prism
line-number CSS (its lines 1442–1481) targeting `.line-numbers-rows > span`.
That DOM is produced by the Prism line-numbers **JavaScript plugin**, which
Obsidian does not bundle — so those selectors never matched anything, and the
feature never worked in Obsidianite either.

Approaches considered and rejected:

| Approach | Why rejected |
|---|---|
| `repeating-linear-gradient` ruler | Cannot show digits; desynchronises on line wrap |
| `::before` with a hard-coded digit string | Wrong for any other line count |
| Counters on `.token` spans | Tokens do not map 1:1 to lines |

Per instruction, the limitation is **documented rather than hacked**.

### Non-interference — asserted by audit

Syntax highlighting · scrolling · wrapping · copy button · language flair ·
plugin-rendered blocks · the code text itself. Numbers are `user-select: none`,
so copying code never picks them up. No `!important`; the gutter rule wins on
specificity `(0,6,1)` vs the base `(0,3,0)`.

## 8. Phase 7 — Gradient / solid separation

### A real bug caught by the audit

The three gradient-based divider styles set `background-color: transparent`
because their gradient image provides the fill. `body.primidian-gradients-off`
removed the image — which would have left the rule **completely invisible**.

Fixed: the off-switch now removes the image **and** restores the flat colour
in the same rule. Both halves are required. The audit asserts the restoration
explicitly so the pairing cannot be broken by a future edit.

Additionally, with gradients off the Animated style retires its shimmer (a
gradient itself, which would degrade to a moving solid block) and returns the
rule to full opacity.

Standard and Minimal explicitly set `--primidian-divider-image: none`, so a
solid-configured style is never given a gradient — the "do not force gradients
onto solid styles" requirement.
